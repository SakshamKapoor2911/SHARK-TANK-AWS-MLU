# Shark Tank App-Build Challenge: Rubric & Evaluation Framework

This framework provides the assessment criteria, scoring methodology, and evaluation prompts for evaluating student solutions built during the sprint.

---

## 1. Core Evaluation Pillars (100-Point Scale)

| Dimension | Weight | Description | Key Evaluative Questions |
| :--- | :---: | :--- | :--- |
| **1. Problem Relevance & Student Impact** | 25% | Tackles an acute, authentic college student pain point with empathy and practical utility. | Does this app solve a real dorm/campus daily struggle? Will students actually use this past Day 1? |
| **2. Feature Completeness (Core Requirements)** | 25% | Full satisfaction of the 3 scenario baseline requirements. | Are all 3 core requirements working as intended? Is the output logically sound and contextually appropriate? |
| **3. Innovation & Stretch Goals** | 20% | Execution of optional stretch goals (multimodal, image gen, adaptive logic, personalization). | Did the team unlock stretch capabilities (e.g., image generation, persona switching, projection calculators)? |
| **4. User Experience & Conversational Tone** | 15% | Intuitive interface, clean layout, engaging student-friendly voice (friendly, empowering, non-judgy). | Is the tone supportive and collegiate? Is the UI uncluttered and easy to navigate? |
| **5. Pitch & Storytelling (2-Minute Pitch)** | 15% | Clarity, charisma, team cohesion, and value proposition articulation during room/stage presentation. | Did the team hook the audience in 15 seconds? Is the startup value proposition immediately crystal clear? |

---

## 2. Granular Scoring Breakdown (1 – 5 Rating Scale)

### Criteria 1: Student Empathy & Problem Definition
- **1 (Deficient)**: Generic app with no college-specific context or clear user persona.
- **3 (Competent)**: Solves a recognizable college problem, but lacks depth or campus nuance.
- **5 (Exemplary)**: Deeply attuned to freshman / student realities (dining hall constraints, tight budgets, exam anxiety, loneliness).

### Criteria 2: Core Feature Implementation
- **1 (Deficient)**: Missing 2+ core required features or buggy prompt execution.
- **3 (Competent)**: All 3 core features present, though outputs may be somewhat generic.
- **5 (Exemplary)**: All 3 core features seamlessly integrated, responsive, and producing rich, high-quality answers.

### Criteria 3: Stretch Goals & Bonus Capabilities
- **1 (Deficient)**: Zero stretch goals attempted or non-functional.
- **3 (Competent)**: 1 stretch goal successfully executed (e.g., basic image prompt or tone tweak).
- **5 (Exemplary)**: 2+ stretch goals working harmoniously (e.g., multimodal visual generator + dynamic personality/difficulty levels).

### Criteria 4: UI / UX & Prompt Design
- **1 (Deficient)**: Unstyled, confusing prompts, dry robotic responses, or broken widget connections.
- **3 (Competent)**: Clean layout, readable fonts, polite and helpful responses.
- **5 (Exemplary)**: Polished aesthetic, intuitive field inputs, delightfully tailored persona (encouraging, witty, authentic).

### Criteria 5: Pitch Delivery & Presentation
- **1 (Deficient)**: Exceeds 2 minutes, rambles, unclear what problem the startup solves.
- **3 (Competent)**: Delivered on time with a clear problem and solution overview.
- **5 (Exemplary)**: Memorable hook, crisp storytelling, passionate team delivery, leaves the room eager to invest/vote.

---

## 3. Peer Voting Guidelines (Breakout Rooms)

Breakout room participants must vote for the most deserving competitor based on:
1. **Who built the most functional and compelling app in 75 minutes?**
2. **Whose pitch was the most engaging and persuasive?**
3. **Which app would you immediately download on your own phone?**

*Rule reminder*: Teams cannot vote for themselves.

---

## 4. Main-Stage Shark Tank Judging Rubric

Head judges (AWS, MLU, Howard leadership) score finalists on 4 "Shark" vectors:
1. **Market Fit**: Is this a viable startup idea for the higher education market?
2. **Technical Ingenuity**: How cleverly did the team leverage generative AI (Amazon Quick / PartyRock) prompt chains and multimodal features?
3. **Execution Velocity**: How much quality was engineered within the tight 60–75 minute constraint?
4. **Stage Presence**: Did the founders pitch like true entrepreneurs?
